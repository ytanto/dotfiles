# Herdr デスクトップ版で動くセッションのルール

このセッションは Herdr デスクトップ版の受信箱パネルが見ている。指示者は多くのセッションを並行で見て回っているので、次の 3 つを守ること。

## 作業の段取りを TaskCreate で登録する

- ツールを 3 回以上使う作業では、最初のツールを使う前に、作業を 3〜7 のステップに分けて TaskCreate で登録する
- 各タスクの `metadata` に `goal` を付ける。goal は、いまの依頼全体で目指すことを 40 文字ほどの 1 行で書き、すべてのタスクで同じ文にする（パネルの見出しになる）
- `subject` は何をするかを短く、`activeForm` は進行中に見せる言い方で書く
- ステップを始めるときに TaskUpdate で `in_progress`、終えたら `completed` にする。`in_progress` は同時に 1 つだけにする
- 段取りが変わったら、タスクを足す・`deleted` にするで直す。指示者の新しい依頼で目指すことが変わったら、新しい goal で登録し直す

## 指示者に選んでもらうときは、AskUserQuestion で出す

- 進め方を指示者に決めてもらうときは、文章で A/B/C や 1/2/3 を並べず、AskUserQuestion で出す。パネルが選択肢をそのまま表示し、選ぶと答えが送られる
- 自分ならどれにするかを必ず決め、それを 1 つ目に置く。その選択肢の `description` は「おすすめ：」で始め、勧める理由を書く。好みの問題で勧める根拠が無いときだけ、おすすめを付けない
- 返答の本文には、選ぶのに要る経緯（何が起きたか・何を確かめたか）だけを書き、選択肢は本文で繰り返さない

## 返答の最後に、次の一手の候補を出す

- 作業を終えて指示者に返すとき、指示者が次に頼みそうなことがあれば、返答の最後に ```next ブロックで 1〜3 個の候補を出す。パネルがボタンにし、押されるとその `prompt` がこのセッションに送られる
- 候補は、指示者が頼めばそのまま進められる作業に限る。進め方を決めてもらう必要があるときは ```next にせず、上の AskUserQuestion で聞く
- 中身は JSON の配列だけにする（コメントや末尾のカンマを入れない）。各要素は次の 3 つ
  - `label`: ボタンの文字。20 文字以内
  - `prompt`: 押されたときに送る指示の全文。それだけで意味が通る文にする（「それで」のような指示語だけにしない）
  - `reason`: なぜ勧めるか。1 文
- いちばん勧めるものを 1 つ目に置く
- 次に頼みそうなことが思いつかないときは出さない
- 例:

```next
[{"label":"Draft PR を作る","prompt":"この変更で Draft PR を作って","reason":"テストが通り、レビューに出せる"}]
```
