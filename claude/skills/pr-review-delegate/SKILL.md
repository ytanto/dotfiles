# PR のレビューを別セッションに任せる

レビューそのものは向こうのセッションの `/pr-review` がやる。ここでやるのは、**正しい場所で起動して、見守って、知らせる**ことだけ。窓の中身は `herdr-app`、端末の状態・画面・送信は `hc` で扱う。

## 決まりごと

- **向こうのセッションに文字やキーを送り込まない**（`hc send`・`hc keys`）。承認ボタンを押すのも同じ。承認や質問への答えは、指示者が向こうのタブ（質問なら受信箱パネルからも）で直接する
- **後片付けは向こうのセッションがやる。** worktree の削除は、向こうのセッションが「レビュー完了」を受けてからやる
  - 指示者がこちらに「レビュー完了」と言ったら、向こうが `done` か `idle` なのを確かめ、`hc read <端末> --lines 20` で入力欄（`❯` の行）が空なのを確かめてから `hc send --wait --timeout 600 <端末> "レビュー完了"` で伝える（指示者に頼まれた、この 1 文だけは送ってよい）。`hc send` は入力欄に文字があるとその後ろにつなげるので、文字があれば送らずに指示者に伝える。入力欄に薄く出る「次の発言の候補」は、送った文にはつながらない
  - `--wait` で、送ったことで始まった向こうのターン（片付け）が終わるまで待つ。送った直後は向こうの状態がまだ `done` のことがあり、別に `hc wait` を始めると片付けを待たずに抜ける
  - 片付けが終わったら、worktree が消えたのを `ls` で確かめる
  - worktree が消えたのを確かめたら、聞かずにタブを閉じる（タブ ID を `herdr-app ls` で取り直して `herdr-app do tab.close --id <タブID> --confirmed true`）。閉じたら、`herdr-app ls` から消えたことを確かめて報告し、`/resume` の一覧からタブ名で開き直せると添える。Claude の `/exit` は、裏で動くシェルがあると確認が出るので使わない
  - worktree が消えていないときは、タブを閉じずに向こうの画面の内容を伝えて指示者の判断を待つ
- タブは `--focus false` で作り、指示者の見ている画面を奪わない
- ID（スペース `sp…`・タブ `tb…`・端末 `t12`）は毎回 `herdr-app ls` で取り直す。前に見た ID を使い回さない

## 手順

### 1. デスクトップ版の中か確かめる

`$HC_TERMINAL_ID` が無ければデスクトップ版の端末の外なので、そう伝えて止める。

### 2. 対象のリポジトリを決める

1. `gh pr view <PR URL> --json number,title,body,headRefName,baseRefName` で PR の情報を取る
2. 手元のクローンを探す。`~/src` の下で、`git remote get-url origin` が PR のリポジトリと一致するディレクトリを使う（ディレクトリ名がリポジトリ名と違う、改名前の名前のままのことがある）
3. 見つからない・複数あるときは指示者に聞く

### 2.5. PR が複数なら、セッションの分け方を決める

- **関連する PR は 1 つのセッションにまとめる。** フロントとバックのセットは必ずまとめる（繋ぎ目の API の契約・文言の受け渡しは、両方を見ないとレビューできない）
  - 関連の目安: 同じ Issue を参照している、本文で互いを参照している、ブランチ名がそろっている、片方の変更をもう片方が使う
- **関連しない PR は、PR ごとに別のセッションを起動する**（3〜5 を PR の数だけ回す）
- どちらか迷うときは、根拠を添えて指示者に聞く

まとめるとき:
- 起動するディレクトリは、変更の起点になる側（フロントとバックならバック、呼び出す側と呼ばれる側なら呼ばれる側）のリポジトリのルートにし、他のリポジトリは `--add-dir` で足す
- 起動の指示に、すべての PR URL と「関連 PR なので 1 本の統合報告にまとめ、PR 間の繋ぎ目も観点に入れる」ことを書く

### 3. タブを作って起動する

1. `herdr-app ls` のスペースの名前と `folder` から、リポジトリに合うスペースを選ぶ。合うものが無ければ指示者に聞く
2. タブを作って起動する。返ってきた `terminal`（`t12` など）を控える
   ```sh
   herdr-app do tab.new --space <スペースID> --name <タブ名> --folder <リポジトリの絶対パス> \
     --argv '["claude","-n","<タブ名>","--remote-control","<タブ名>","/pr-review <PR URL>"]' --focus false
   ```
   - タブ名は PR の中身を日本語 6 文字以内に要約する（例: `ログイン文言`）。PR 番号は使わない（サイドバーで何のレビューか分からない）
   - `-n` でセッションの表示名をタブ名とそろえる（タブを閉じたあとも `/resume` の一覧でどのレビューか分かる）
   - `--remote-control` を付ける（指示者がスマホからレビューの結果を見て答えられるように。2026-11-25 に指示者が決めた）。名前は省略できる引数なので、**必ずタブ名を続けて書く**（省くと、次に置いたプロンプトが名前として読まれ、空のプロンプトで立ち上がる）
   - `argv` は配列で渡すので、プロンプトにクォートの入れ子が要らない
   - まとめるときは `["claude","-n","<タブ名>","--remote-control","<タブ名>","/pr-review <PR URL> <PR URL> 関連 PR なので…","--add-dir","<他のリポジトリの絶対パス>"]`
   - **プロンプトは `--add-dir` より前に置く。** `--add-dir` は値を複数取るので、後ろに置いたプロンプトまでディレクトリとして読まれ、空のプロンプトで立ち上がる
   - 指示者から追加の指示（「重くていいから全部見て」など）があれば、PR URL の後ろに続けて書く

### 4. 起動を確かめて報告する

数秒おいて `hc get <端末> --json` の `status.state` が `working` になったのを確かめる。「このフォルダを信頼するか」の画面で止まっていたら（`status.kind` が `permission`、初めて開くフォルダ）、自分では選ばず、指示者に伝えて待つ。

**スキルが起動したかまで確かめる**（Claude が立ち上がっただけで、入力欄が空のまま・プロンプトがただの文章として扱われている、ということがある）。1〜2 分おいて `hc read <端末> --lines 200` で読み、次がそろっていれば起動している:
- 入力欄に `❯ /pr-review <PR URL>…` が載っている
- `pr-review` の手順どおり、PR の情報の取得 → `references.local/` の読み込み → 規模の見積もり → worktree の作成、と進んでいる

そろっていなければ、画面の内容を伝えて指示者の判断を待つ。

報告: スペース名・タブ名・ディレクトリ・PR のタイトルと URL。

**起動・承認待ち・結果、どの報告でも PR の URL を添える**（指示者がそのまま PR を開けるように）。

### 5. 見守る

状態が `blocked`（承認・入力待ち）か `done` / `idle`（手を止めた）になるまで、バックグラウンドで待つ。`run_in_background` で次を流し、終わったら通知で戻ってくる。`hc wait` は、時間切れや自分あてのメッセージでも抜けるので、状態を見て待ち直す。

```bash
while :; do
  hc wait <端末> --timeout 1800 >/dev/null
  s=$(hc get <端末> --json | perl -MJSON::PP -e 'print decode_json(join "", <STDIN>)->{status}{state} // ""')
  case "$s" in blocked|done|idle) echo "$s"; break ;; esac
done
```

戻ってきたら `hc get <端末> --json`（`status.kind`・`status.msg`）と `hc read <端末> --lines 150` で読み、状態ごとに次のようにする。

| 状態 | やること |
| --- | --- |
| `blocked` | 何で止まっているかを、`status.kind`（`question` は質問、`permission` は承認）と向こうの画面の文面に即して短く伝える。承認なら「向こうのタブで答えてください」、質問なら「向こうのタブか受信箱パネルで答えてください」と添え、5 の待機をもう一度流す |
| `done` / `idle` で統合報告が出ている | 所見を要点だけまとめて伝える（重大度・件数・各所見の一行要約）。全文は向こうのタブにあると添える。まとめの HTML のパスが出ていれば、それも 1 行で添える。見守りはここで終わり |
| `done` / `idle` で統合報告が無い | 途中で止まっている。最後の画面の内容（エラー・質問）を伝えて、指示者の判断を待つ |

報告のあと、「レビュー完了」と言ってもらえれば向こうに伝えて worktree を消してもらい、タブも閉じる、と添える。
